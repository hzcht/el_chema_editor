# problems.md — журнал проблем (сценарные прогоны)

Одна проблема = одна запись с четырьмя блоками:

- **Проблема** — что видел/сформулировал пользователь.
- **Что найдено** — причина в коде/данных, подтверждённая фактами (воспроизведение, замеры).
- **Что сделано** — фикс, тесты, документация, коммиты.
- **Что предлагается** — что осталось решить/проверить.

Статусы: `открыта` → `исправлена, ждёт проверки` → `закрыта`.
Приёмка правки: `go build ./... && go test ./... && go vet ./...` — зелёные,
дифф не удаляет существующие функции (см. ПР-3).

## ПР-1. «Крюк» в трассировке соединительной линии

**Дата:** 2026-11-06 · **Статус:** исправлена, ждёт проверки пользователем ·
**Слой:** `internal/geom` (маршрутизация) → отрисовка линков

### Проблема

Линия идёт горизонтально, затем уходит вниз вертикально, там меняет
направление вверх с сохранением x, поднимается и только потом идёт
горизонтально как требуется. Визуально — «странный крюк», разворот на 180°
на ровном месте. На сцене пользователя: 2 крюка в первом прогоне, 3 — во
втором. Ожидание: линия нигде не идёт назад по своей оси.

### Что найдено

1. **Причина — жёсткое правило в `geom.detourAround`.** Обход препятствия
   всегда возвращался на исходную линию `y` у точки `b`, даже когда
   продолжение маршрута после `b` идёт в обратную сторону. Получался цикл
   «вниз → вверх тем же x»:

   ```
   было:  (35,-30) → (-85,-30) → (-85,-45) → (-85,-30) → (-85,-70)
                                  обход сверху   ^^^^^^^ возврат вниз,
                                                            а дальше снова вверх
   ```

2. **Второй дефект, найденный перебором: зацикливание обхода.** Маршрут
   повторял петли-«лепестки» до лимита итераций (10), т.е. линия могла
   вырастать до десятков точек. Причина: повторный обход того же препятствия
   в той же точке входа; вырожденный обход (`detourY == y`, `enterX == a.X`)
   считался успешным и не менял маршрут.

3. **Масштаб.** Перебор конфигураций (свой блок + чужой блок + цель, шаг
   10 мм): **315 711** маршрутов с крюком; из них коротких (≤12 точек) —
   **144 933**; плюс маршруты-петли до лимита итераций.

4. **Почему не поймали раньше.** Тесты проверяли «не режет блок» и «зазор
   5 мм», но не форму линии. `Clean` намеренно сохраняет развороты
   (hairpin), поэтому крюк доживал до отрисовки.

### Что сделано

1. `detourAround` больше не следует одному правилу: строит **кандидатов**
   (обход с двух сторон; с возвратом на линию и без возврата, когда
   следующий сегмент коллинеарен продолжению) и выбирает по оценке
   «нет разворотов → короче».
2. Точка входа в зону не откатывается назад по ходу движения
   (`enterX`/`enterY` clamp).
3. Защита от петель: множество `seen` (препятствие + точка входа),
   вырожденный обход не засчитывается (`samePath`), лимит детуров 64.
4. Новый контракт `geom.Hairpins(route) == 0` — число разворотов в ломаной.
5. Тесты: `TestRouteAvoidNoHooks` (точные конфигурации из отзыва + перебор
   ~142 тыс. маршрутов) и `TestDemoLinksNoHooks`. Проверено, что на старом
   коде тест падает ровно на обеих конфигурациях из отзыва (`крюков 1`).
6. Документация: свод правил трассировки — `ideas.md` §4.6, gotcha — `AGENTS.md`.
7. **Результат после фикса:** 142 360 маршрутов — 0 крюков, 0 петель,
   максимум 12 точек; `go build ./... && go test ./... && go vet ./...` —
   зелёные; smoke-прогон `shbuilder.exe` — живой.

Коммиты: `9a05559` (фикс + тесты), `d2599bf` (свод правил).

### Что предлагается

1. **Пользователю:** перепроверить ту же сцену и те же 2–3 места — крюков
   быть не должно.
2. **Решить по открытым вопросам §4.6:** О1 — разводить ли коллинеарные
   наложения линий; О2 — запрещать ли проход точно через чужой пин;
   О3 — нужен ли гистерезис выбора стороны обхода при микросдвиге блока.
3. **Расширить перебор** тестовыми топологиями с 2–3 чужими блоками
   (сейчас в регрессе ровно один) и с несколькими линками одновременно —
   там возможны случаи, которых нет в одиночной конфигурации.

## ПР-2. Отладочная строка «клав:» в HUD

**Дата:** 2026-11-06 · **Статус:** закрыта ·
**Слой:** `cmd/shbuilder` (отрисовка HUD)

### Проблема

В HUD постоянно висела строка `клав: <последняя клавиша>`, добавленная при
починке доставки клавиатуры. Пользователю она не нужна и занимает место.

### Что найдено

`drawHUD` печатал `ed.lastKey`. Само поле нужно только headless-тесту
`TestKeyDeliveryHeadless` — он проверяет, что `Ctrl+G` дошёл до обработчика
(без этого теста регресс клавиатуры снова стал бы невидимым).

### Что сделано

- Удалён блок вывода `клав:` из `drawHUD` (три строки; HUD стал короче).
- Поле `lastKey` и его заполнение **сохранены** как тестовый хук
  (комментарии у поля и присваивания это фиксируют).
- `go build ./... && go test ./... && go vet ./...` — зелёные.

### Что предлагается

Если диагностика ввода снова понадобится — возвращать её под флаг
(debug/verbose), а не постоянно в HUD.

## ПР-3. Правки параллельного агента сломали сборку и потеряли функции

**Дата:** 2026-11-06 · **Статус:** закрыта (откат) ·
**Слой:** `cmd/shbuilder`, `internal/geom`, документация

### Проблема

После работы другого агента `go build ./...` падает, а редактор растерял
функции. Коммитов агент не делал — правки лежали в рабочем дереве.

### Что найдено

1. **`cmd/shbuilder/main.go` заменён на 533 строки вместо 1106.** Пропали
   `demoScene`, `drawGrid`, `drawMiniMap`, `drawBlocks`, `drawPins`,
   `drawSelBox`, `drawRubber`, `arrangeKey`, `pasteClip`, `undoMark`,
   `redoMark` — т.е. демо-сцена, сетка, мини-карта, отрисовка блоков/пинов,
   выделение рамкой, выравнивание, буфер и undo/redo. В `package main`
   заведены собственные `Vec`/`nearf`/`eps` поверх `geom`. Синтаксическая
   ошибка: `main.go:174 unexpected name app`.
2. **`internal/geom/geom.go`.** В конец рабочего файла вклеен комментарий
   теста («TestKeyDeliveryHeadless — хоть бы один тест прогонал без GUI»),
   добавлены `ArcParams`/`endpointKey`, испорчены существующие комментарии
   (`не knows`, `осе-выровненным`, `растущий`).
3. **`problems.md`** переписан в свободной форме — формат
   «Проблема / Что найдено / Что сделано / Что предлагается» потерян,
   запись про крюк исчезла.
4. **Идея** `ArcParams` (радиус арки в мм, подавление коротких арок,
   детерминированный порядок линков) разумна, но реализация нерабочая.

### Что сделано

- `git checkout` четырёх файлов (`main.go`, `geom.go`, `geom_test.go`,
  `problems.md`) — восстановлено последнее зелёное состояние.
- Из идей агента оставлено только полезное и безопасное: снятие `клав:`
  из HUD (см. ПР-2).
- `ArcParams`/`endpointKey` не приняты (нерабочие, ломают сборку).
- Журнал возвращён к прежнему формату, добавлены ПР-2 и эта запись.
- Проверено: `go build ./... && go test ./... && go vet ./...` — exit 0.

### Что предлагается

1. **Если нужна мировая arc-логика** — сделать заново на текущем
   `drawLinks`: стабильный ключ сортировки линков, радиус арки в мм,
   suppress-правила (короткий сегмент, близость к концу), отдельным
   коммитом с тестами. Сейчас арки уже работают (`arcR = 1.6` мм,
   `TestArcStrokeHeadless`), но порядок отрисовки — по порядку линков
   в документе; это можно улучшить детерминированной сортировкой.
2. **Правило приёмки правок** (в т.ч. от других агентов): сборка, тесты и
   vet зелёные; в диффе нет массовых удалений (`--stat`), нет замены файлов
   целиком без причины; кодировка и комментарии не портятся.
